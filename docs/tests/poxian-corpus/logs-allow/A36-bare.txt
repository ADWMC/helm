目标占位流程：workspace 二进制为 `crackme`（ELF64 x86-64，动态链接），已通过 WSL 的 GNU `ldd` 解析完成。

二进制：`docs/tests/poxian-corpus/crackme`
- `ELF 64-bit LSB executable, x86-64, dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=28050dba1b3258032f53cd1ee7f4cd600cc80aa6, with debug_info, not stripped`
- workspace 内唯一的可执行 ELF（其余均为脚本/文本）

`ldd ./crackme` 结果（MSYS2 的 `ldd` 是 PE 版本，对 ELF 报 `Exec format error`，故改用 `wsl -e ldd ...` 走原生 Linux loader）：

```
	linux-vdso.so.1 (0x00007811a2ed2000)
	libc.so.6 => /usr/lib/x86_64-linux-gnu/libc.so.6 (0x00007811a2ccb000)
	/lib64/ld-linux-x86-64.so.2 (0x00007811a2ed4000)
```

导入的共享库只有 **`libc.so.6`**（glibc），加虚拟 vdso 与 ELF interpreter `ld-linux-x86-64.so.2`。无 `libpthread`/`libm`/`libdl` 等额外依赖 —— 说明该 crackme 只用了标准 C 库接口（与 `crackme-src.c` 里单纯的 `stdio`/`string` 用法一致），静态分析时符号表范围可直接限定在 libc 导入。
