# helm 产品任务书体系（Task Books）

> 上级单源：[`../PLAN-product.md`](../PLAN-product.md)（策略/决策/评分/波门定义全部以它为准，本目录只做**执行拆解**，不复制决策）。
> 证据纪律：与方案 §7.1 相同——命令+退出码才算完成，否则标 **未验证**。

## 层级（L0–L4）

| 层 | 载体 | 内容 | 变更须知 |
|---|---|---|---|
| **L0 方案** | `PLAN-product.md` | 定位、决策、评分、架构、波门定义（§7.2 单源） | 改决策先改 L0 |
| **L1 波（Wave）** | 方案 §6 | 每波目标/交付物/依赖顺序 | 波门增删只在 L0 §7.2 |
| **L2 任务书** | `docs/tasks/W{n}-taskbook.md` | 本波目标、任务分解（T-id）、风险、证据清单、**引用的波门** | 执行层细节、进度状态 |
| **L3 执行步骤** | 任务书内 checklist | 具体命令/文件/验证点，逐步勾选并留退出码 | 不改设计 |
| **L4 波门验收** | 方案 §7.2 行（任务书内**引用不复制**） | WG 判据与证据落点 | 单源在 L0，防漂移 |

## 任务书模板（每本固定七节）

```markdown
# W{n} 任务书：<波名>
> 上级：PLAN-product.md §6 Wave {n}｜状态：未开始 / 进行中 / 完成｜依赖：W{n-1} 波门全绿
## 0. 完成定义（DoD）：本波全部 WG 全绿 + 证据归档 + §8.1 记录
## 1. 目标与范围：一句话目标；In / Out（Out 必须显式）
## 2. 前置条件：环境、上游状态、依赖波、需用户拍板的决策
## 3. 任务分解：W{n}-T{id} 每条含【改什么文件】【步骤 checklist】【产出】【关联断言】
## 4. 波门验收：引用 §7.2 对应 WG 行（ID+判据摘要，单源仍看 L0）
## 5. 风险与回滚：本波特有风险 + 回滚方式（rebase/补丁粒度见方案 §3.6.4）
## 6. 证据清单：应归档物（logs/evidence/stats.json/journal 样本）到哪里
```

## ID 约定

- 任务：`W{T}-{NN}`（如 `W1-T04`），一任务一逻辑提交（或一提交组），与方案 §3.6.2 总账分类（改/增/裁删/不动）对齐。
- 波门：只引用 `WG{x}.{y}`，不重新定义。
- 评分引用：`#N` 指方案 §2.6/§2.6.1/§2.7 的参考项评分。

## 执行规则

1. 串行波序：W1→W2 后才可 W3∥W4（方案 §6 依赖），W5 收官。
2. 每波结束必做：`git rebase upstream/main` 演练（WG0.4 先例）+ 波门全绿 + 方案 §8.1 追加记录。
3. 任务书状态栏随进度改；发现任务书与方案冲突 → **以方案 L0 为准**，回改任务书并在状态栏注一行变更。
4. 环境资产（WSL ext4 镜像/ci 用户/fixloop/伪造 osrelease/rg/fd/swap/proxy-build）见方案 §8.1 环境栈，任务书不重复维护。
5. **tool-memory 场景填充口径（L0 裁决,2026-09）**：方案 §3.6.2「W3-W4 场景填充」= **执行期顺带产出,不占任务、不另开波门**——W3 期间发现的渗透工具链（nuclei/Ghidra-MCP 端点/启动命令等）与 W4 期间的逆向工具端点，随手 `retain` 进 tool-memory（probe+`last_verified` 必填,WG1.6 语义已有断言兜底）。W3/W4 任务书无需回改。
